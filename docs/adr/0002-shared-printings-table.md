# Scryfall data for search lives in a shared `printings` table

Filtering the collection by type, subtype or legal format must run in SQL, so the full type line and legalities are kept per `scryfall_id` in `printings`, the only table without a `user_id`. A background `printing.Refresher` fills unknown printings every 2 minutes and refreshes those older than 24 h, so a new card is searchable within minutes and a ban shows up the next day. Deck insights (`deckinsights`) read `printings` too, so a deck's legality and statistics can be up to 24 h behind Scryfall, the same as search. The reason is consistency of totals between collection, storage and deck views and independence from Scryfall, not load: deck insights no longer call Scryfall at all.
