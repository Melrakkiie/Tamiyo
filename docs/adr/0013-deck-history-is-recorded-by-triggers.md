# Deck history is recorded by database triggers, as net daily counts per card name

A deck's history is written by triggers on `card_deck` and `deck_pending_cards`, which add each change in copies to one row per deck, day (Europe/Paris), board and card name, and drop the row when it nets to zero. Service methods record nothing themselves. A deck changes through a dozen write paths, existing triggers included (a card deleted from the collection becomes a pending card). Many of those paths swap one row for another without changing the deck for the player: committing a pending card, switching finish or proxy, splitting printings. Netting by card name in the database makes those swaps cancel out on their own and covers write paths added later. Recording in each service method would need every path to remember to do it and to work out which of its changes are real. The cost: history keeps only net daily counts per name, not individual moves or printings, and the cascade from deleting a deck must not write history for that deck.
